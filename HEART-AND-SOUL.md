# HEART-AND-SOUL.md

## MACS Design + Editing Constitution

This file is a mandatory pre-edit check for all meaningful MACS Digital Media copy, UX, UI, landing-page, mobile, portfolio, and conversion work.

Before every edit, ask which of these disciplines applies and use it deliberately. Do not stack frameworks mechanically; apply the smallest set needed to improve the user outcome.

## Required Skill Stack

### 1. Landing Page Director — Repo-Agnostic
Use for landing pages, hero copy, offer framing, CTA hierarchy, proof, objections, and conversion flow.

Core test:
- What must the visitor understand in the first 2 seconds?
- What pain or desired outcome is most urgent?
- What is the single primary action?
- What proof makes the claim believable?

### 2. Art of Reduction / ADHD Elegant Simplicity
Use for all user-facing copy, workflows, forms, navigation, and interaction design.

Ask repeatedly:
- Can this be removed?
- Can this be combined?
- Can this be shorter?
- Can this appear only when needed?
- Can the system infer or remember it?
- Can the next action be more obvious?

Optimize for:
minimum cognitive effort + minimum physical effort + maximum confidence + maximum usefulness.

### 3. COLLINS-Level Website Design Protocol
Use for strategy, editorial composition, art direction, proof, distinctiveness, page structure, and final design quality.

Non-negotiables:
- Strategy before styling.
- Distinction before decoration.
- Content before containers.
- Self-evident before experimental.
- Proof before claims.
- Do not imitate COLLINS visually; imitate the rigor.

### 4. Apple-Level Mobile / Premium UX Discipline
Use for responsive behavior, touch interactions, motion, forms, navigation, and mobile polish.

Rules:
- Mobile is not compressed desktop.
- Design separately for thumb reach, interruption, limited attention, and small screens.
- Controls should acknowledge touch immediately.
- Prefer transform/opacity for motion.
- Support reduced motion.
- No scroll hijacking.
- No hover-only essential behavior.
- Aim for practical touch targets around 44x44 CSS px.

### 5. ICM / Brownfield Evidence Discipline
Use before changing existing systems.

Required behavior:
- Inspect before changing.
- Preserve what already works.
- Know the blast radius.
- Keep one owner per truth.
- Runtime evidence outranks repository intent.
- Keep TESTED, PREVIEW VERIFIED, and PRODUCTION VERIFIED distinct.
- Preserve rollback.

### 6. Gauntlet / Anti-Slop Review
Use after meaningful implementation.

Attack the work for:
- value;
- clarity;
- usability;
- originality;
- mobile behavior;
- accessibility;
- performance;
- truthfulness;
- conversion;
- unnecessary complexity.

Reject generic AI/SaaS aesthetics, decorative motion, fake metrics, weak proof, template card walls, and visual polish that hides an unclear offer.

### 7. Netlify Portfolio Curator
Use when discovering, validating, or populating Work / Collaborations / Built Here from deployed projects.

Rules:
- deployment evidence is not business-result proof;
- reconcile duplicates;
- client work stays separate from MAXX Suite products;
- never invent case-study outcomes;
- use real project media when available;
- placeholders must describe the exact missing evidence or asset.

## Pre-Edit Gate

Before changing anything user-facing, answer internally:

1. USER OUTCOME — what does this edit help the visitor accomplish?
2. PAIN / TRIGGER — what real problem or desired outcome is being addressed?
3. PRIMARY ACTION — what should the visitor do next?
4. REDUCTION — what can be removed or combined first?
5. PROOF — what evidence supports the claim?
6. MOBILE — how does this work intentionally on phone?
7. ACCESSIBILITY — can it be used with keyboard, touch, zoom, and reduced motion?
8. MOTION — what information does any movement communicate?
9. DISTINCTIVENESS — does this feel specifically like MACS rather than a generic agency?
10. ROLLBACK — how is the change safely reversed?

If the edit cannot answer these questions, do not ship it yet.

## MACS Copy Laws

- Clarity first, metaphor second.
- Outcome before mechanism.
- Avoid AI / agentic / orchestration / automation language in primary marketing unless the product itself requires it.
- One section, one job.
- One page, one primary action.
- Default CTA: **Tell us what’s important.**
- Use short, concrete, human language.
- Remove generic corporate filler.
- Never invent proof.

## Mobile Law

Every important page must be reviewed as its own mobile composition.

At minimum inspect:
320 / 360 / 375 / 390 / 414 / 430 / 768 / 1024 / 1440 px.

Mobile success means:
- no unintended horizontal overflow;
- intentional content order;
- intentional image crops;
- readable type hierarchy;
- clear navigation;
- practical touch targets;
- no desktop tables or grids squeezed into phone;
- no hidden critical actions;
- immediate interaction feedback.

## Final Standard

Make the system powerful.
Make the experience simple.
Keep the human in control.
Prove what is true.
Remove everything else.
